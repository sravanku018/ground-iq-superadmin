Implementation Pattern

useAsyncData hook — used by every admin screen
// src/hooks/useAsyncData.js export function useAsyncData(key, fetcher, { staleMs = 30_000 } = {}) { const [data, setData] = useState(() => readCache(key)) const [loading, setLoading] = useState(!data) useEffect(() => { // 1. Serve from cache immediately const cached = readCache(key) if (cached && Date.now() - cached.ts < staleMs) { setData(cached.data) setLoading(false) return // fresh — skip network } // 2. Show stale data while refreshing if (cached) setData(cached.data) // 3. Fire background refresh setLoading(true) fetcher() .then(d => { writeCache(key, d); setData(d) }) .catch(() => {}) // keep stale on failure .finally(() => setLoading(false)) }, [key]) return { data, loading } }

Doctrine: Built for the Low End

[G] LOW-END Google assumes a cheap phone on a bad network — your surveyor's exact reality. Cache-first means the UI is always instant. Network is a background optimization, not a gate.
[T] REFRESH ON OPEN Every tab switch triggers a background refresh. Data is never more than one tab-open stale. "Pull-to-refresh" without the pull — the refresh happens automatically.
[G] OFFLINE-FIRST Cache persists in localStorage. Kill the app, reopen — data is there. Network failure keeps stale data visible. The app works without a connection.
